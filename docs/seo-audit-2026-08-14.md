# SEO audit — www.avlokai.com

Date: 2026-08-14
Method: live crawl of all 14 indexable routes + the 404, parsing `<title>`, meta
description, canonical, Open Graph, Twitter, heading counts, JSON-LD types, and
image `alt` coverage; plus `robots.txt`, `sitemap.xml`, `llms.txt`, and response
headers for the apex and `www` hosts.

Severity key: **P0** breaks indexing or a rich result · **P1** measurably costs
clicks or rankings · **P2** hygiene / future-proofing.

---

## P0 — indexing correctness

### 1. Every non-home page shipped a doubled brand suffix in `<title>`

`src/app/layout.tsx` declared `title.template = '%s | AvlokAI'`. In the App
Router a template applies to **child** segments only, so `app/page.tsx` (same
segment as the root layout) was exempt while all 13 other routes were not — and
every one of those already carried `| AvlokAI` in its own title. Result:

| Route | Live title |
|---|---|
| `/privacy` | `Privacy Policy \| AvlokAI \| AvlokAI` |
| `/terms` | `Terms of Service \| AvlokAI \| AvlokAI` |
| `/services` | `AI Automation Services \| AvlokAI — Hyderabad \| AvlokAI` |
| `/services/document-automation` | `Document Processing & Back-Office Automation \| AvlokAI \| AvlokAI` |

13 of 14 pages affected. Duplicated tokens dilute the title, push the real
keywords past the SERP truncation point, and read as low quality.

**Fix:** `pageMetadata` now emits `title: { absolute: title }`, which opts out of
the parent template entirely. The template stays in the layout purely as a
fallback for any route that forgets to call `pageMetadata`.

### 2. The 404 page declared a canonical pointing at the homepage

`layout.tsx` set `alternates: { canonical: SITE_URL }` at the root. Every route
that did not override it inherited it — including `not-found`, which returned
`200`-style metadata with `<link rel="canonical" href="https://www.avlokai.com">`
on a `404` response. That tells Google every wrong URL *is* the homepage, which
is exactly the signal that causes soft-404 consolidation and phantom URLs in the
index.

**Fix:** removed the root-level canonical. Canonicals are now issued only by
`pageMetadata`, which every real page calls, so the 404 emits none.

### 3. Homepage canonical and sitemap URL disagreed on trailing slash

- Canonical: `https://www.avlokai.com` (no slash)
- Sitemap `<loc>`: `https://www.avlokai.com/` (slash)

Two URL forms for one page. Minor on its own, but it is the kind of drift that
splits link signals.

**Fix:** `SITE_URL` is unchanged, but the homepage canonical is now produced by
`url('/')`, the same helper the sitemap uses, so both emit the trailing-slash
form.

## P1 — click-through and rich results

### 4. Meta descriptions overflowed on 14 of 15 pages

Measured lengths: 218, 172, 185, 139, 207, 212, 175, 220, 192, 176, 193, 178,
214, 210, 246. Google truncates around 155–160 characters, so the closing clause
of nearly every description — usually the differentiator ("deployed to your own
cloud", "documented at handover") — never rendered.

**Fix:** every description rewritten to ≤ 160 characters with the differentiator
moved to the front half.

### 5. Titles overflowed

Homepage was 84 characters; six others sat between 53 and 68 *before* the
doubled suffix was counted. Target is ~60.

**Fix:** all titles rewritten to ≤ 55 characters.

### 6. `twitter:card` was `summary_large_image` with a 512×512 square image

`og:image` was `/AvlokAi.png`, declared `512×512`. A large-image card wants
1200×630 at roughly 1.91:1. Twitter/X, LinkedIn, and Slack all letterbox or
centre-crop a square into that frame, so the shared card was a small logo on
grey. There was no dedicated share image anywhere in `public/`.

**Fix:** added `src/app/opengraph-image.tsx`, a `next/og` `ImageResponse` route
that renders a real 1200×630 branded card at build time. Because it uses the
file convention at the app root it applies to every route, and Next reuses it
for `twitter:image` automatically. `pageMetadata` no longer hard-codes the
512×512 dimensions.

### 7. Homepage and `/ai-automation-agency-hyderabad` competed for one query

Both targeted "AI automation agency in Hyderabad" with near-identical titles and
descriptions. Classic cannibalisation: Google picks one, and it may not be the
one you want.

**Fix:** the homepage title now leads with the brand
(`AvlokAI — AI Automation Agency in Hyderabad`) and the location page takes the
transactional variant (`Hire an AI Automation Agency in Hyderabad | AvlokAI`).
Content was left alone — retargeting the homepage's body copy is a positioning
decision, not an audit fix. Worth watching in Search Console.

### 8. `sitemap.xml` reported a fresh `lastmod` on every build

`sitemap.ts` used `new Date()`, so all 14 URLs claimed to have changed at build
time. Telling a crawler everything changed is equivalent to telling it nothing
changed; it degrades crawl scheduling.

**Fix:** `lastModified` now reads from a per-route constant date, updated only
when a route's content actually changes.

## P2 — hygiene

### 9. `robots.txt` emitted an invalid `Host` directive

Output was `Host: https://www.avlokai.com/`. The `Host` directive is a
Yandex-only extension that Google and Bing ignore, and the value is meant to be
a bare hostname, not a URL with scheme and trailing slash. It was noise at best.

**Fix:** removed.

### 10. No web app manifest, no `theme-color`

Both are PWA/mobile-quality signals surfaced by Lighthouse, and `theme-color`
controls the browser chrome tint on Android.

**Fix:** added `src/app/manifest.ts` and a `viewport` export carrying
`themeColor` for light and dark schemes.

### 11. `WebSite` schema had no `inLanguage`

**Fix:** added `inLanguage: 'en-IN'`, matching `<html lang>`.

### 12. `ProfessionalService` schema was missing local-business fields

No `priceRange`, no `openingHoursSpecification`, no `currenciesAccepted`. Google
treats `priceRange` as an expected property for `LocalBusiness` subtypes and
warns on its absence in the Rich Results Test.

**Fix:** all three added. `priceRange` is `$$`, consistent with the "fixed price,
no published rate card" position in `llms.txt`.

### 13. `FAQPage` nodes had no `@id`

Anonymous nodes cannot be referenced or deduplicated across the graph.

**Fix:** `faqSchema` now takes the page path and emits a stable
`{url}#faq` `@id` plus an `isPartOf` link to the `WebSite` node.

### 14. The 404 had no metadata of its own

It inherited the homepage title and description verbatim.

**Fix:** `not-found.tsx` now exports its own title and description, with
`robots: { index: false, follow: true }`.

## Verified clean — no action needed

- **`h1` discipline** — exactly one `<h1>` on all 15 URLs crawled.
- **Image `alt`** — 0 missing and 0 empty across every page.
- **Canonical host** — `www` resolves `200`, all canonicals and sitemap entries
  agree on it.
- **`robots` meta** — `index, follow` on all real pages, `noindex` on the 404.
- **Breadcrumbs** — `BreadcrumbList` present on all 13 non-home pages.
- **`Service` schema** — present on `/services` and all six detail pages.
- **`generateStaticParams`** — all six service slugs are statically rendered.
- **Sitemap coverage** — all 14 routes present, all return `200`, none orphaned.
- **`llms.txt`** — present, `200`, current, and unusually good: explicit
  not-offered list and an accuracy-notes section that pre-empts the Avlok Kohli
  brand collision.
- **HSTS** — `max-age=63072000` on both hosts.

## Outside the codebase — needs a Vercel dashboard change

**The apex redirect is a `307`, not a `308`.**

```
$ curl -sI https://avlokai.com/
HTTP/1.1 307 Temporary Redirect
Location: https://www.avlokai.com/
```

A temporary redirect does not consolidate link equity onto the `www` host the
way a permanent one does, and Google will keep re-crawling the apex
indefinitely. The comment in `src/lib/company.ts` asserted the server "301s apex
→ www"; it does not. The comment has been corrected, but the redirect itself is
set at the Vercel edge, before Next.js runs — `next.config.js` `redirects()`
cannot reach it.

**Action for the site owner:** Vercel → Project → Settings → Domains →
`avlokai.com` → change the redirect to `www.avlokai.com` from temporary to
permanent (`308`). This is the single highest-value item left after this pass
and it cannot be fixed from this repository.
